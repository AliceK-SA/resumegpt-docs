# Итоговый отчёт

Сборка итогового отчёта о проектной работе по ГОСТ 19.105-78.

Отчёт — сводка документов из каталога `docs/`. При сборке автоматически формируются:

- таблица записей журнала ADR — из файлов `docs/adr/`;
- таблицы операций HTTP API и сообщений — из спецификаций OpenAPI и AsyncAPI;
- таблица сервисов и таблица рисков — из Markdown arc42;
- рисунки — из исходников Mermaid в `docs/arc42/`.

Поясняющий текст отчёта написан вручную в `report.js`.

## Сборка

Нужны Python 3 с PyYAML, Node.js с пакетом `docx`, Mermaid CLI, LibreOffice и `pdftotext`.

```bash
npm install --prefix report docx@9.8.1
bash report/build.sh        # результат: report/build/report.pdf и report.docx
```

Адреса сайта и репозитория подставляются из переменных окружения, иначе остаются пустые строки для заполнения:

```bash
SITE_URL=https://<логин>.github.io/<репозиторий>/ REPO_URL=https://github.com/<логин>/<репозиторий> bash report/build.sh
```

В CI отчёт собирается при каждом изменении и сохраняется как артефакт запуска `report`.

## Снимок экрана прогона CI

Если в каталоге есть файл `report/ci-run.png`, он вставляется в отчёт как рис. 1; если нет — вместо него печатается нейтральный текст о том, что подтверждение публикации будет добавлено позже. Снимок добавляется в репозиторий отдельным коммитом после первого успешного прогона.

### Контроль пагинации

`build.sh` должен выполняться в окружении с установленным Node.js `docx` и LibreOffice. Генератор выполняет несколько проходов, пока страницы содержания и количество листов не стабилизируются, и отклоняет сборку при расхождении. При отсутствии зависимостей готовые DOCX/PDF можно редактировать отдельно, но они не заменяют проверку воспроизводимости генератора.

## Ограничение локальной проверки

Готовые DOCX и PDF могут иметь отличия оформления от результата последующей CI-сборки,
если использовалась ручная правка документа или иная версия LibreOffice.
Файлы отчёта необходимо проверять **после сборки из `report/report.js` в CI**,
а не только по ранее подготовленному Word.
Для сообщений AsyncAPI теперь дополнительно проверяются примеры payload по JSON Schema.
