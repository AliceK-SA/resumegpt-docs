# ResumeGPT — документация архитектуры

AI-консультант по карьере: анализ и улучшение резюме под конкретную вакансию.

**Команда «CodeCortex»:** Климович Алиса, Петроченко Платон, Хамадалиева Эльвира.

Итоговый отчёт содержит поля для официального имени преподавателя и нормоконтролёра: их необходимо заполнить по данным кафедры.

Проектная работа по теме «Подготовка и публикация документации в рамках концепции „Документация как код“».

## Как это устроено

- Тексты — Markdown, диаграммы — Mermaid (GitHub рисует их прямо в файлах), контракты — OpenAPI 3.0 и AsyncAPI 3.0.
- Страницы справочника API генерируются из спецификаций скриптом `scripts/gen_api_reference.py`.
- PNG-копии диаграмм для отчёта и слайдов генерируются скриптом `scripts/render_diagrams.py` и в репозитории не хранятся.
- Итоговый отчёт в формате ЕСПД собирается скриптом `report/build.sh`; таблицы ADR, API, сервисов и рисков извлекаются из исходных файлов. Согласование отдельных разделов с ГОСТ 19 не равно полному соответствию всем требованиям ЕСПД.
- Workflow GitHub Actions запускает линтер Markdown, валидаторы OpenAPI и AsyncAPI, проверку контрактов и неизменности принятых ADR, сборку сайта и отчёта. Успешный запуск и настройка обязательных проверок ветки `main` ещё требуют подтверждения в GitHub. Публикация на GitHub Pages предусмотрена, но будет проверена отдельно.

Подробности и правила ведения — в [`docs/about.md`](docs/about.md).

## Быстрый старт

```bash
pip install -r requirements-docs.txt
mkdocs serve
```

Сайт откроется на <http://127.0.0.1:8000>.

## Структура

```text
docs/
  index.md            главная страница
  arc42/              описание архитектуры, разделы 1–12
  adr/                журнал архитектурных решений
  api/                справочник API и спецификации
  assets/diagrams/    PNG-копии диаграмм (генерируются, в Git не хранятся)
  about.md            правила ведения документации
scripts/              генерация справочника, проверки, рендер диаграмм
team/                 внутренние материалы команды (шпаргалка к защите)
report/               сборка итогового отчёта по ГОСТ 19.105
mkdocs.yml            настройки сайта
.github/workflows/    автоматические проверки и публикация
```

## Проверки до публикации

```bash
python scripts/check_specs.py
python scripts/check_contract_rules.py
python scripts/check_adr_append_only.py  # без BASE_SHA проверяет структуру; в CI — сравнение с базовой веткой
python scripts/gen_api_reference.py --check
# После установки зависимостей запускайте также валидацию OpenAPI, AsyncAPI и mkdocs build --strict
```

В архив не входят Java-исходники, `pom.xml`, `docker-compose.yml` и настройки защиты ветки GitHub. Поэтому точные версии серверных библиотек, производительность и реальную работу сервисов нельзя считать подтверждёнными. См. `ПРОВЕРКА_И_ОГРАНИЧЕНИЯ.md`.
