# Журнал архитектурных решений (ADR)

ADR (Architecture Decision Record) — короткая запись об одном значимом решении: в какой ситуации его принимали, из чего выбирали, что выбрали и чем за это платим. Формат предложен Майклом Найгардом и широко используется в подходе «документация как код».

## Правила ведения журнала

1. **Append-only.** Принятая запись не редактируется по существу. Допустимы только изменение строки статуса при замене и строки «Заменяет», если прежний текст не содержал её. Исправления опечаток в принятых записях не допускаются: для содержательных правок создаётся новый ADR.
2. **Изменение решения — новая запись.** Новый ADR получает следующий номер и статус «Принято», в поле «Заменяет» указывается прежняя запись. У прежней записи меняется только статус: «Заменено ADR-000N».
3. **Одна запись — одно решение.** Если решений несколько, заводится несколько записей.
4. **Обязательные разделы:** Контекст, Варианты (минимум два, с плюсами и минусами), Решение, Последствия.
5. **Участники:** поле обязательно для новых ADR (у исторических записей 0002–0005 оно отсутствовало и не добавляется задним числом).
6. **Новая запись проходит ревью.** ADR добавляется через pull request, который одобряет хотя бы один участник команды, не являющийся автором.

## Статусы

| Статус | Значение |
|---|---|
| Предложено | Запись на обсуждении, решение ещё не принято |
| Принято | Решение действует |
| Отклонено | Решение рассмотрено и не принято; запись остаётся в журнале как история |
| Заменено ADR-000N | Решение больше не действует, действует указанная запись |

## Шаблон

```markdown
# ADR-000N. Название решения

- **Статус:** Предложено | Принято | Отклонено | Заменено ADR-000M
- **Дата:** ГГГГ-ММ-ДД
- **Участники:** ФИО или инициалы участников принятия решения
- **Заменяет:** ADR-000K (если есть)

## Контекст

Какая проблема, какие ограничения, почему решать надо сейчас.

## Варианты

Минимум два, у каждого плюсы и минусы.

## Решение

Что выбрали и главный довод.

## Последствия

Что становится лучше, чем платим, что нужно помнить.
```

## Автоматический контроль

`scripts/check_adr_append_only.py` сравнивает принятые/заменённые ADR с базовым коммитом. Старые записи разрешено менять только в строке статуса и поле `Заменяет`; новые записи должны содержать поле `Участники`. В CI для pull request и push используется базовый SHA, предоставленный GitHub Actions.
