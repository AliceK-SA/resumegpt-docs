# 8. Сквозные концепции

Правила, которые действуют во всех сервисах сразу.

| Концепция | Правило | Подробнее |
|---|---|---|
| Идемпотентность HTTP | Изменяющие запросы клиента (`POST /analyses`, `POST /purchases`) принимают `Idempotency-Key`; ключ и ответ хранятся 24 часа. Внутренние вызовы идемпотентны по бизнес-ключу: резерв — по `analysisId`, платёж — по `purchaseId` | [ADR-0002](../adr/0002-outbox-and-idempotent-consumers.md) |
| Надёжная отправка сообщений | Сообщение пишется в таблицу `outbox` той же транзакцией, что и изменение данных; relay отправляет его в брокер | [ADR-0002](../adr/0002-outbox-and-idempotent-consumers.md) |
| Защита от дублей сообщений | Получатель в одной транзакции записывает `eventId` в `inbox` и выполняет работу; второй рубеж — условные `UPDATE` и уникальные индексы | [ADR-0002](../adr/0002-outbox-and-idempotent-consumers.md) |
| Переходы статусов | Каждый переход — условный `UPDATE … WHERE status = :expected`; если обновилось 0 строк, переход уже сделан кем-то другим | [Раздел 6](06-runtime.md) |
| Ошибки API | `application/problem+json` (RFC 9457): `type`, `title`, `status`, `detail` | [Справочник API](../api/index.md) |
| Деньги и кредиты | Деньги — целое число копеек (`amountMinor`) и `currency`; кредиты — целые числа. Без `float` | [Справочник API](../api/index.md) |
| Время и идентификаторы | Время — ISO 8601 в UTC; идентификаторы — UUID | [Справочник API](../api/index.md) |
| Трассировка | `X-Request-Id` в HTTP, `correlationId` в сообщениях. По `correlationId = analysisId` находятся все логи и сообщения одного анализа | [Справочник API](../api/index.md) |
| Аутентификация | API Gateway проверяет JWT и передаёт `X-User-Id`; заявка видна только владельцу. Внутренний API (`/internal/...`) наружу не публикуется | [Раздел 3](03-context-and-scope.md) |
| Вебхуки ЮKassa | Не доверяем содержимому: проверяем IP отправителя и сами запрашиваем статус платежа у ЮKassa | [Раздел 6](06-runtime.md) |
| Персональные данные | Файлы резюме удаляются по правилу 30 дней; срок результатов и порядок удаления должны быть утверждены до реального запуска | [ADR-0005](../adr/0005-database-per-service-and-object-storage.md) |
| Версионирование сообщений | Новые поля добавляются обратно совместимо; несовместимое изменение — новый тип сообщения с суффиксом `.v2` | [AsyncAPI](../api/asyncapi.md) |

## 8.5. Обработка персональных данных (требует проверки до реального запуска)

Пользователь загружает резюме; analysis-service хранит исходный файл в MinIO, ai-worker извлекает текст через Tika и передаёт текст резюме и текст вакансии во внешний Groq API. В hh.ru API передаётся идентификатор вакансии, а **не содержимое резюме**. Результат и диагностическая информация могут сами содержать персональные данные.

Требуется отдельно определить правовое основание обработки, состав передаваемых полей, уведомления/согласия, поставщика и фактическую страну обработки, применимость требований 152-ФЗ о трансграничной передаче и локализации, договор с внешним обработчиком, доступы и порядок удаления. Нельзя заявлять о соответствии законодательству без юридической проверки конкретной конфигурации и условий внешнего поставщика.

Файлы MinIO: проектное ограничение 30 дней из ADR-0005. **Результаты, резервные копии и журналы:** срок хранения и регламент удаления пока не утверждены; до ввода сервиса их необходимо зафиксировать, обеспечить удаление по запросу при наличии основания и исключить полный текст резюме из обычных логов. Доступ к объектам MinIO по принципу минимальных привилегий; TLS, секреты вне репозитория, аудит операций и проверка изоляции арендаторов.
