# 1. Введение и цели

## 1.1. Назначение системы

ResumeGPT помогает соискателю подготовить резюме под конкретную вакансию. Пользователь загружает резюме (PDF или DOCX) и ссылку на вакансию с hh.ru. Система получает текст вакансии, сравнивает его с резюме с помощью LLM (Groq) и возвращает:

- оценку ATS-совместимости резюме;
- найденные пробелы в навыках;
- улучшенные формулировки;
- сопроводительное письмо (в продвинутом режиме).

## 1.2. Тарифы

| Функция | Базовый анализ | Продвинутый анализ |
|---|---|---|
| Стоимость | Бесплатно, без ограничений | 1 кредит за анализ |
| Очередь | Общая | Приоритетная: платные задачи идут первыми |
| Модель LLM | Базовая | Более сильная |
| Сопроводительное письмо | Нет | Да |
| Архив результатов | Да | Да |

Кредиты продаются пакетами (например, 10 продвинутых анализов за 79 ₽) и оплачиваются через ЮKassa.

## 1.3. Основные функции

1. Приём заявки на анализ: файл резюме, ссылка на вакансию, режим.
2. Асинхронный анализ: заявка ставится в очередь, клиент опрашивает статус.
3. Архив результатов анализа пользователя.
4. Каталог пакетов кредитов, покупка пакета, баланс и история движений кредитов.
5. Резерв кредита под продвинутый анализ, его списание после успеха или возврат при неудаче.

## 1.4. Цели качества

Цели перечислены по убыванию важности. Подробные сценарии — в [разделе 10](10-quality.md).

| № | Цель | Что это значит для ResumeGPT |
|---|---|---|
| Q1 | **Сохранность денег** | Купленный кредит нельзя потерять и нельзя списать дважды. Оплату пакета нельзя зачислить дважды. Если анализ не удался, кредит возвращается |
| Q2 | **Устойчивость к сбоям** | Недоступность Groq, hh.ru, ЮKassa или падение одного из сервисов не теряет заявки и сообщения, а только задерживает их |
| Q3 | **Масштабируемость анализа** | Тяжёлую часть — AI-обработку — можно масштабировать отдельно от API, запуская больше копий воркера |
| Q4 | **Отзывчивость** | Пользователь получает ответ на запуск анализа сразу, не дожидаясь LLM; платные анализы обгоняют бесплатные |
| Q5 | **Понятность** | По статусу заявки в любой момент видно, на каком шаге процесс и что произойдёт при сбое |

## 1.5. Заинтересованные стороны

| Роль | Что важно знать из документации |
|---|---|
| Соискатель (пользователь) | Что даёт каждый тариф; что кредит вернётся, если анализ не удался |
| Команда разработки (CodeCortex) | Границы сервисов, контракты API и сообщений, правила идемпотентности, принятые решения |
| Преподаватель (проверяющий) | Обоснованность архитектуры, полнота и оформление документации |
| Внешние системы: Groq, hh.ru, ЮKassa | Какие вызовы мы делаем, с какими таймаутами и повторами |

## 1.6. История системы

Первая версия (демо) была монолитом: Spring Boot API без базы данных, который сам парсил файл, ходил на hh.ru и в Groq и сразу возвращал ответ. В плане развития следующими шагами стояли платные тарифы через ЮKassa, хранение файлов в S3, отдельный AI-воркер и очередь анализов в RabbitMQ. Описанная здесь архитектура — результат этого развития.

Архитектура описывает систему для части 2 проекта, в которой она реализуется на Java 21 и Spring Boot.
