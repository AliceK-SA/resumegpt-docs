# 9. Архитектурные решения

Все значимые решения ведутся в [журнале ADR](../adr/index.md) в режиме append-only: принятая запись не редактируется, а при изменении решения создаётся новая запись со ссылкой на прежнюю.

| № | Решение | Статус | Цели качества |
|---|---|---|---|
| [ADR-0001](../adr/0001-saga-with-credit-reservation.md) | Анализ — сага с оркестратором и резервированием кредита | Принято | Q1, Q5 |
| [ADR-0002](../adr/0002-outbox-and-idempotent-consumers.md) | Transactional Outbox и идемпотентные получатели | Принято | Q1, Q2 |
| [ADR-0003](../adr/0003-rabbitmq-priority-queue.md) | Асинхронный анализ через RabbitMQ с приоритетной очередью | Принято | Q3, Q4 |
| [ADR-0004](../adr/0004-stateless-worker-with-lease.md) | ai-worker без своей базы, аренда без продления | Заменено ADR-0007 | Q1, Q2, Q3 |
| [ADR-0007](../adr/0007-lease-renewal-fencing.md) | Продление аренды и токен попытки | Принято | Q1, Q2, Q3 |
| [ADR-0008](../adr/0008-payment-reconciliation.md) | Восстановление платежа после таймаута | Принято | Q1, Q2 |
| [ADR-0005](../adr/0005-database-per-service-and-object-storage.md) | Своя база у каждого сервиса, файлы — в MinIO, в сообщениях — только ссылки | Принято | Q2, Q3 |
| [ADR-0006](../adr/0006-docs-as-code.md) | Документация как код | Принято | Q5 |

Цели качества Q1–Q5 описаны в [разделе 1](01-introduction-and-goals.md).
