# 2. Ограничения

Ограничения — это условия, которые команда не выбирает, а принимает как данность. Они сужают пространство решений.

## 2.1. Технические ограничения

| Ограничение | Причина и следствие |
|---|---|
| Java 21 и Spring Boot для всех сервисов | Стек команды и первой версии продукта. Используем Spring Cloud Gateway, Spring AMQP, springdoc-openapi |
| Анализ выполняет внешняя LLM — Groq API | Своей модели нет. Бесплатные лимиты Groq приводят к ответам `429 Too Many Requests`, поэтому нужны повторы и очередь |
| Вакансии берутся из hh.ru API | Внешний сервис может быть недоступен или вернуть `404`, если вакансия удалена |
| Оплата — только через ЮKassa | Платёж подтверждается вебхуком, который может прийти повторно или не прийти вовсе |
| Учебная версия запускается на ноутбуке студента через docker-compose | Один сервер PostgreSQL с тремя базами, один узел RabbitMQ, без Kubernetes |
| Файлы резюме: PDF или DOCX не больше 5 МБ | Ограничивает расход памяти на парсинг и размер хранилища |

## 2.2. Организационные ограничения

| Ограничение | Следствие |
|---|---|
| Команда из 3 человек, учебный проект | Отказываемся от тяжёлой инфраструктуры: Kafka, Debezium, Temporal/Camunda ([ADR-0002](../adr/0002-outbox-and-idempotent-consumers.md), [ADR-0001](../adr/0001-saga-with-credit-reservation.md)) |
| Часть 1 — только архитектура, часть 2 — реализация | Контракты пишутся заранее, код в части 2 пишется по контрактам |
| Регистрация и вход — вне задания | API Gateway принимает готовый JWT и передаёт в сервисы заголовок `X-User-Id` |
