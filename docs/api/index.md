# Справочник API

Контракт — это обещание сервиса: какие запросы он принимает и что отвечает, какие сообщения публикует и в каком формате. В части 2 код пишется **по контрактам**, и любые их изменения сначала вносятся сюда.

## Синхронные вызовы — OpenAPI 3.0

| Сервис | Кто вызывает |
|---|---|
| [analysis-service](analysis-service.md) | Веб-клиент (запуск анализа, статус, архив); ai-worker (аренда задачи) |
| [billing-service](billing-service.md) | Веб-клиент (пакеты, баланс, покупка); analysis-service (резерв кредита) |
| [payment-service](payment-service.md) | billing-service (создать платёж); ЮKassa (вебхук через Gateway) |

У `ai-worker` нет своего HTTP API: он только слушает очередь, вызывает чужие API и публикует результаты.

## События и команды — AsyncAPI 3.0

[События и команды](asyncapi.md) — все сообщения системы.

| Routing key | Тип | Кто публикует | Кто слушает |
|---|---|---|---|
| `analysis.requested` | **команда** | analysis | ai-worker (очередь `ai.jobs`, с приоритетом) |
| `analysis.completed` | событие | ai-worker | analysis |
| `analysis.failed` | событие | ai-worker | analysis |
| `credits.commit-requested` | **команда** | analysis | billing |
| `credits.release-requested` | **команда** | analysis | billing |
| `payment.succeeded` | событие | payment | billing |
| `payment.failed` | событие | payment | billing |

**Событие** — сообщение о факте, который уже произошёл («оплата прошла»). Отправитель не знает, кто его слушает.
**Команда** — просьба конкретному сервису что-то сделать («верни кредит»).

Списание и возврат кредита — именно команды через брокер, а не REST-вызов: если billing-service в этот момент недоступен, команда подождёт в очереди и не потеряется.

## Соглашения для всех контрактов

| Тема | Соглашение |
|---|---|
| Деньги | Целое число копеек (`amountMinor`) + `currency`. Никаких `float` |
| Кредиты | Целые числа |
| Время | ISO 8601 в UTC |
| Идентификаторы | UUID |
| Файлы | В сообщениях передаётся только путь в MinIO (`resumeObjectKey`), не сам файл |
| Ошибки | `application/problem+json` (RFC 9457): `type`, `title`, `status`, `detail` |
| Идемпотентность HTTP | Заголовок `Idempotency-Key` на изменяющих запросах клиента; внутренние вызовы идемпотентны по бизнес-ключу (`analysisId`, `purchaseId`) |
| Идемпотентность сообщений | `eventId` в конверте, получатель хранит его в `inbox` |
| Трассировка | `X-Request-Id` в HTTP, `correlationId` в сообщениях |
| Пользователь | Браузер передаёт JWT в `Authorization: Bearer`; Gateway проверяет его, удаляет поддельный клиентский `X-User-Id` и устанавливает доверенный `X-User-Id` для внутренних сервисов |
| Таймауты | Межсервисный HTTP — 2 с; hh.ru — 5 с; Groq — 45 с (внутри попытки до 2 повторов); ЮKassa — 5 с |

## Как устроен справочник

Источник истины — файлы спецификаций в каталоге `docs/api/`:

| Файл | Формат |
|---|---|
| [`openapi/analysis-service.yaml`](openapi/analysis-service.yaml) | OpenAPI 3.0.3 |
| [`openapi/billing-service.yaml`](openapi/billing-service.yaml) | OpenAPI 3.0.3 |
| [`openapi/payment-service.yaml`](openapi/payment-service.yaml) | OpenAPI 3.0.3 |
| [`asyncapi/events.yaml`](asyncapi/events.yaml) | AsyncAPI 3.0.0 |

Страницы справочника генерируются из них скриптом `scripts/gen_api_reference.py` и вручную не правятся. При каждом изменении CI проверяет, что спецификации валидны, а справочник соответствует им.

## Как посмотреть интерактивно

- OpenAPI — в [Swagger Editor](https://editor.swagger.io) или плагином OpenAPI в IntelliJ IDEA.
- AsyncAPI — в [AsyncAPI Studio](https://studio.asyncapi.com).
- В части 2 Swagger UI от springdoc-openapi может использоваться для диагностики фактической реализации, **но не как второй источник требований**. В CI необходимо сравнивать маршруты, параметры, ответы и схемы `/v3/api-docs` с файлами OpenAPI из этого каталога. До появления Java-кода тест недоступен.

## Условия применения и безопасность

- Публичные вызовы (кроме общедоступного каталога пакетов) требуют Bearer JWT, который проверяет API Gateway. Внутренние вызовы требуют отдельного сервисного токена; конкретная выдача и проверка токена реализуется в части 2.
- `401` означает отсутствие/ошибку авторизации, `403` — недостаточные права, `429` на `POST /analyses` — более 10 запусков в минуту на пользователя на шлюзе.
- `GET /analyses` и `GET /credits/history` используют страницы, `page` с нуля и `size` 1–50.
- Вебхук ЮKassa не использует пользовательский JWT, проверяет источник и подтверждает состояние независимым запросом к провайдеру.
- Требуются Java 21, сервисы и инфраструктура из [раздела 7 arc42](../arc42/07-deployment.md). Конкретные версии и лимиты ресурсов будут уточнены при реализации; контракты версии `1.0.0` не подтверждают работоспособность Java-кода.
